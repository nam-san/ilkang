# (주)일강이앤지 통합 창호 공사 관리 시스템

창호 전문 공사 기업의 **현장 관리 · 인건비 집계 · 견적 · 하도급 이력**을 통합 관리하는 웹 시스템입니다.

## 기술 스택

- **Next.js 14** (App Router) + **TypeScript** + **TailwindCSS**
- **Prisma + SQLite** (파일 기반 DB — 별도 서버 설치 불필요, 추후 PostgreSQL/MySQL 전환 가능)
- **FullCalendar** (대시보드 캘린더), **SheetJS(xlsx)** (엑셀 견적 파싱), **Lucide** (아이콘)

## 실행 방법 (Windows)

```bash
cd ilkang-web

# 1) 최초 1회: 의존성 설치 (이미 설치되어 있으면 생략)
npm install

# 2) 최초 1회: 데이터베이스 생성
npm run db:push

# 3) (선택) 샘플 데이터 넣기
npm run db:seed

# 4) 개발 서버 실행 → http://localhost:3000
npm run dev
```

운영(빌드) 실행: `npm run build` 후 `npm run start`

## 창호 견적 산출 (Phase 1)

엑셀(`내역서_공종명`, A~BY) 수작업 견적을 웹으로 전환. 계산은 서버 API에서 단일 수행(`src/lib/windowCalc.ts`).

- **공사 생성** → 공사(Project) 단위로 기준값·비용 스냅샷 관리
- **① 기준값 관리** — 창호유형·부재·**단위중량(kg/M)**·비용파라미터 CRUD(개수 가변). `기본 기준값 채우기`로 엑셀 기준값 템플릿 로드
- **② 엑셀 업로드·라인 검토** — A~N 파싱하여 라인 생성, 규격 정규식 파싱(`1.100 x 1.150` → W1100·H1150), 파싱 실패 하이라이트 + 수동보정, 창호유형 자동추천/지정
- **③ 자재 산출** — 창호유형 부재로 물량 자동채움 `길이=(W·개수W+H·개수H)/1000`, `중량=길이×단위중량`, 라인 총중량 = 부재 중량 합. 부재 치수 라인별 수동조정 가능
- **④ 비용 계산 · 견적서 (Phase 2)** —
  - 총자재비 `=ROUNDUP(kg당자재비×총중량+흰지+방충망, -2)`, 시공비 `=ROUNDUP(총중량×kg당시공비, -2)`, 총시공비 `=시공비+PJ시공비`
  - **단가 자동연동**: 총자재비→재료비단가, 총시공비→노무비단가. 수동조정 시 `수동` 배지 + 자동값 대비 차이 표시 + 원클릭 복원 (현행 엑셀의 단가 미연동 문제 해결)
  - **견적 금액**: `금액=TRUNC(단가×수량)`, 계층 그룹 소계(00.공통/01.아파트/1-1…) + 총계
- **⑤ 엑셀 익스포트** — `비용 계산·견적서` 탭의 `엑셀 다운로드` (`GET /api/estimate-projects/{id}/export-excel`, exceljs)
  - 시트1 `견적내역서`: 원 시트 레이아웃(제목·공사명·단가/금액 병합헤더·계층 그룹 소계·총계) + 총중량/총자재비/총시공비 요약열
  - 시트2 `자재산출`: 라인별 부재 물량 상세(W/개수/H/개수/단위중량/길이/중량 + 라인 총중량)
- 계산 단위테스트: `npm run test` (엑셀 R23 실측 대사 15건 — 물량·비용·금액)
- **다음 단계:** 원 시트의 O~BM(창호유형별 컬럼 블록) 완전 재현, 다단계 SUM 계층 정밀화

## 데이터베이스

- 파일 위치: `prisma/dev.db` (SQLite)
- 스키마: `prisma/schema.prisma` — Contract, Worker, DailyAssignment, DailyLog, Bid, EstimateItem, SubcontractorEstimate, SubcontractorCompany, Todo, Memo, EstimateProject, WindowType, WindowComponent, CostParam, EstimateLine, LineComponent
- GUI로 데이터 확인: `npm run db:studio`
- 근무일지 이미지: `public/uploads/` 에 저장

## 확장 참고

- 견적의 단가 산출/상세 원가 분석은 데이터 구조(`EstimateItem.unitPrice` 등) 확장성을 확보해 둔 상태로, 별도 단계에서 구현 가능합니다.
- 실시간 동기화는 현재 주기적 폴링(TO-DO 5초 / 메모 4초) 방식이며, 필요 시 WebSocket으로 고도화할 수 있습니다.
- 로그인/권한, 클라우드 이미지 저장(AWS S3)은 향후 단계에서 추가 가능합니다.
